## Recurring failure groups and decisions

1. **P3: missing semantic catalog (3).** Damped motion, quadratic shape and
   market equilibrium produced valid Comparison item IDs, but semantic_catalog
   only consumes flow/map nodes. Their existing labs cannot reach planning.
   Fix catalog coverage using those canonical IDs and their actual cell pages;
   provide deterministic concept identity only when no structured IDs exist.
2. **Compiler declaration coupling (4).** RC charging fails on duplicate IDs in
   an unused finite-state declaration; finite sampling has annotations only,
   yet those trigger required_process. These are **C4** optional-field-fatal
   errors inside the runner's broad C1 group. Future lifecycle and recursive
   calls have genuinely invalid process mechanics (singleton stage variables,
   invalid initial/from/to values, missing targets); **C1/C3** must remain
   rejected, not guessed into executable semantics. Isolate bounded unused
   process data from non-process plans, and clarify variable/values/transition
   semantics in the prompt. Keep the strict required process validator.
3. **P1/C5: parametric interaction confused with animation (1).** Vector
   resultant has a validated numeric lab and useful parameter control, but the
   proposal is static because time evolution is absent. Current choose() also
   makes dynamic eligibility require time. Reuse the numeric lab for
   parameterized functions independently of elapsed time. Advertise precise
   adapter capabilities to the model rather than add another renderer.

No topic-name branches, no new parser, physics solver, statechart framework or
renderer is justified by these observations. Stronger process semantics cannot
